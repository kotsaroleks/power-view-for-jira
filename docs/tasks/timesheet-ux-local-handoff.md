## Поточне уточнення: hover і спливні деталі worklog

Після inline-checkpoint нижче користувач прямо змінив вимогу до кнопки «…» біля годин:
пояснення при наведенні та деталі у спливному вікні. `WorklogDetailsButton` показує
підказку на hover/фокусі, `WorklogDialog` використовує native modal dialog з Esc,
поверненням фокусу й захистом незбереженого редактора. Редагування/видалення/додавання з
деталей відбуваються в тому самому вікні. Основні години далі вводяться в таблиці.
Попередні заборони modal для деталей у checkpoint нижче замінено цією вказівкою; заборона
dropdown для вибору задач залишається чинною.

Перевірено: 131 тест Day Off/Timesheet/Time Report, web TypeScript та ESLint змінених
файлів; web/extension/content build і validate/package пройшли. У встановленому Chrome
відкрито деталі реального worklog у popup, перевірено Esc і перехід до редагування в тому
самому вікні; форму закрито без збереження. Збірку оновлено у `dist/extension` та ZIP.

## Уточнення UX, погоджені користувачем 2026-11-02

- Задачі обраної борди — усі доступні задачі її збереженого фільтра, а не лише видимі в
  колонках борди.
- Остаточний порядок груп:
  1. Закріплені задачі незалежно від Assignee: користувач явно обрав їх через pin.
  2. Решта задач із власним worklog за обраний тиждень, включно із задачами поза бордою.
  3. Пріоритетний Epic LBR-68393 та його нащадки (додаткове доручення користувача).
  4. Решта задач борди, призначених поточному користувачу.
  5. Усі інші задачі борди у початково згорнутій ієрархії Epic → Story → Task/Subtask.
- Задачі без Epic/Story — окрема група «Без батьківської задачі».
- Кожна задача відображається один раз, у першій відповідній групі; її час також
  враховується один раз. Розгортання ієрархії не дублює задачі з попередніх груп.
- Введення часу — безпосередньо в тижневій таблиці, без dropdown вибору задач і зайвих
  обов'язкових полів.
- Ці уточнення замінюють попередню послідовність «pin → призначені мені» та відповідь про
  розташування чужих pin після власних задач. Повторно погоджувати цей порядок не
  потрібно.
- Погоджені уточнення реалізовано локально; актуальні перевірки наведено нижче. Історичні
  результати попередньої реалізації не є перевіркою нового UX.

## Підтверджені правила запису, які не потрібно знову питати

- Новий worklog: 09:00 дати комірки, обраний часовий пояс.
- Один worklog: редагувати тривалість зі збереженням timestamp і коментаря.
- Кілька worklog: окремі записи через деталі, без автоматичної зміни суми.
- Власні задачі: Assignee поточного акаунта в обраній борді; власний час:
  author.accountId.

## Уточнення після зауваження про popup

Користувач мав на увазі модальне вікно Log time поверх табеля. Це відхилений UX. Загальні
кнопки Log time прибрано; нова сесія починається з Week, навіть якщо раніше збережено
Month. Основний вибір задач та введення годин — лише на сторінці табеля. Додатковий
редактор конкретної задачі/запису — звичайна вбудована секція перед таблицею, без
dialog/showModal/overlay. Перемикання цілі редактора проходить через dirty guard і
перемонтовує редактор для нової задачі, щоб не переносити старий issue/draft. Порожня
комірка місячного огляду переводить у тижневий табель для введення.

## Реалізація та незалежні перевірки 2026-11-02

- Реалізовано чотири групи в погодженому порядку, дедуплікацію рядків, початково згорнуту
  ієрархію та групу Without parent issue. Діти батьків, показаних у попередніх групах,
  доступні під структурним заголовком Children of, без другого облікового рядка батька.
- Dropdown задач/Epic/Story прибрано. Вибір борди залишається select. Основний UX не
  використовує додаткову форму для вибору задач; лише рядки головної таблиці.
- Метадані всіх задач борди не спричиняють читання всіх worklog. Непрочитані комірки й
  підсумки позначені `?`; дія Add to table або клік у комірку читає конкретну задачу,
  після чого комірка отримує фокус для введення. Розгортання дерева саме не читає worklog.
- Pin поза фільтром борди відновлюється прямим getIssue; лише фактична помилка читання
  показує недоступність. Збережено ізоляцію instance/account/board.
- Незалежний аудит агентів і додатковий аудит іншою моделлю GPT-6 Astra виявили та
  допомогли виправити приховування призначених дітей, неправдиві нулі непрочитаних задач,
  втрату зовнішніх pin та чернеток при Refresh. Додано регресійні тести.
- Невідомий результат запису зберігає блокування і чернетку в межах API-сесії після
  перемонтування комірки; повторна спроба потребує явного підтвердження перевірки Jira.
- 54 тести табеля пройшли в незалежному запуску, включно з новими перевірками зовнішніх
  pin і двох чернеток при оновленні. Окремо 48 тестів адаптера/request policy/handler
  пройшли. Web/extension typecheck і lint файлів табеля та production E2E пройшли.
- Production E2E пройшов у встановленому Google Chrome з mocked Jira: CRUD, чотири групи,
  чужий pin першим, розгортання Epic/Story/Subtask та inline-введення `1,5` із записом
  5400 секунд. Це перевірка production UI з фікстурами, не реального Jira instance.
- Web, extension worker і content script перебудовані разом; validate-extension пройшов,
  архів перепаковано. Поточний SHA-256: див. `dist/power-view-for-jira-0.3.0.zip.sha256`.
  Історичний SHA нижче стосується попереднього архіву, не актуальної збірки.
- Початковий запуск Playwright не знайшов bundled Chromium; встановлений Chrome вдався

  `docs/qa/timesheet-ux-2026-11-02/`.
- Візуально перевірено viewport 1440×900 і 1280×800; при 1280×800 браузерний тест

  симуляція масштабу, не перевірка нативного browser zoom. На ньому глобальна навігація

## Локальні команди

Спочатку перевірити наявність runtime, залежностей та поточні scripts у package.json.
Попередньо використовувався `/tmp/power-view-timesheet-node` — локальна копія bundled Node
з ad-hoc підписом для завантаження native Rollup. Тимчасовий файл може вже не існувати.
Bundled оригінал: `/Applications/ChatGPT.app/Contents/Resources/cua_node/bin/node`. Не
стверджувати, що runtime/залежності відсутні, без перевірки.

При наявному `/tmp/power-view-timesheet-node`, з кореня репозиторію:

```sh
/tmp/power-view-timesheet-node node_modules/vitest/vitest.mjs run apps/web/src/app/timesheet --maxWorkers=1 --no-file-parallelism
/tmp/power-view-timesheet-node node_modules/typescript/bin/tsc --noEmit -p apps/web/tsconfig.json
/tmp/power-view-timesheet-node node_modules/typescript/bin/tsc --noEmit -p apps/extension/tsconfig.json
```

Для збірки: Vite web → Vite extension → Vite content config → validate-extension →
package-extension. Не збирати лише web: UI та worker можуть стати несумісними.
Команди/шляхи звірити з package.json.

Playwright раніше завершувався ще на запуску Chromium:
`bootstrap_check_in ... MachPortRendezvousServer ... Permission denied (1100)`, SIGTRAP.
Це зафіксований результат конкретних запусків, не доказ загальної неможливості скріншотів.
Повторно перевірити доступні засоби браузера; не вигадувати скріншоти або результати
візуального QA.
