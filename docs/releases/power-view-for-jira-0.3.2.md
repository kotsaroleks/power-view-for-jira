# Power View for Jira 0.3.2

> Public copy: personal addresses, live account identifiers and private spreadsheet URLs
> are redacted. Local originals are kept outside Git.

## Зміни

- Незбережені години захищені під час зміни періоду й фільтрації з клавіатури. Видиме
  повідомлення пояснює блокування та скасування через Escape.
- Групування, пріоритети та ієрархію тижневих задач винесено в окрему модель. Збережено
  погоджений порядок і відсутність дублювання часу.
- Збереження комірки зберігає фокус наступної дати після Tab та не запускає повторне повне
  читання вже завантажених задач. Скасування читання нової закріпленої задачі не залишає
  таблицю заблокованою.
- Settings зберігає завантажену робочу область між переходами. Gantt очікує читання
  налаштувань та показує помилки їх запису з окремою повторною спробою.
- Невдале оновлення Day Off скасовує достовірність норми та utilization, зберігаючи відомі
  позначки як застарілі дані.
- Місячна норма, погоджена користувачем: 8 годин за кожен понеділок–п'ятницю мінус будні
  Day Off. Вихідні не додають норму; повтори Day Off не віднімаються двічі.
- Звіт не позначається повним при зламаній пагінації або досягненні ліміту 5000 задач.
- Виправлено навігацію, накладання елементів шапки, вузьку таблицю та відображення помилок
  комірок. Кнопки мають видимий фокус і стани недоступності.
- Додано неблокуюче попередження, коли пояс автора з Jira-профілю відхиляється від
  Europe/Kyiv більш ніж на ±1 годину. Перевіряються всі дні відкритого періоду з
  урахуванням літнього/зимового часу; показується фактична різниця або її діапазон. Рівно
  ±1 година допустима. Ручний вибір Kyiv для перегляду не приховує попередження про
  Jira-профіль. Часовий пояс береться також зі свіжого читання автора табеля.

## Перевірки

- Повний набір Vitest: 665 тестів у 95 файлах пройшли.
- TypeScript, ESLint без попереджень, Prettier і `git diff --check` пройшли.
- Production web, service worker і content script скомпільовані.
- Валідатор перевірив 10 entry points; ZIP та SHA-256 сформовані.
- Два фінальні production UI сценарії пройшли в ізольованому Chrome з fixtures (9,0 с):
  CRUD, фокус після Tab, помилки вводу, Day Off, місячна норма, адаптивність та перехід
  Kyiv → Jira-профіль із датою 2 листопада. Додатково підтверджено попередження про −10h
  для Los Angeles, його збереження після ручного вибору Kyiv, відсутність записів Jira від
  зміни поясу та відображення попередження на екрані 390 px без переповнення.
- ZIP перевірено через `unzip -t`; SHA-256:
  `d6edd9606e8c3dc0dca29e9c8bce32a82cccb854aff502bab43f3b5ce54827c7`.

Методика: рев'ю потоків даних і запису, асинхронного стану та збереження налаштувань;
повний набір тестів клієнтської збірки; production UI з ізольованими Jira/GitHub fixtures
і візуальним переглядом скриншотів; окреме читання реального worklog для перевірки
повідомленої розбіжності дат. Командний сценарій двох реальних встановлень Day Off цією
перевіркою не підтверджується. Обсяг цієї збірки: Chrome-розширення та спільні
TypeScript-пакети; native macOS має окремий цикл.

## Дата worklog: перевірено в Jira та погоджено

2026-11-03 користувач повідомив розбіжність між Jira й табелем. Читання Jira підтвердило
для повідомленого запису початок `2026-11-02T14:00:00.000-0800`: це 2 листопада 14:00 у
Los Angeles і 3 листопада 00:00 у Kyiv. Поточний табель використовує вибраний Europe/Kyiv,
а профіль автора — America/Los_Angeles. Арифметика перетворення відповідає часовим поясам.
Користувач погодив початкове відображення за поточним Jira-профілем. Його пояс тепер
передається з `/myself` у табель; старий неявний Europe/Kyiv мігрує на цей режим.
Подальший явний ручний вибір іншого поясу зберігається. Для цього запису початковий табель
показує 2 листопада. Регресійні тести перевіряють обидва пояси та незмінність початкового
timestamp. Жодних записів Jira під час перевірки не змінено.

## Встановлення

Розпакувати `dist/power-view-for-jira-0.3.2.zip`. У `chrome://extensions` вибрати
«Завантажити розпаковане розширення» та папку з `manifest.json`. Для оновлення замінити
файли в папці чинного встановлення й перезавантажити розширення. Публікація та
встановлення в особистий профіль Chrome не виконувались.
