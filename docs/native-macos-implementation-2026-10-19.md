# Нативний Power View — стан переробки

Дата: 2026-10-19. Завдання: перенести Chrome Power View у Swift-застосунок і додати
функціональну дошку естимації. Актуальні критерії —
[продуктове ТЗ](native-macos-product-spec.md). Попередній опис збережено в
[архіві](native-macos-implementation-before-rework.md), первинне ТЗ —
[окремо](native-macos-product-spec-2026-10-16.md).

## Запуск

З кореня репозиторію:

```sh
sh scripts/build-native-macos.sh
```

Результат: `apps/macos/dist/Power View.app`. Нативний SwiftUI/AppKit, macOS 14+,
перевірено на Apple Silicon. Локальний ad-hoc підпис; нотаризація, дистрибуція та
автооновлення не завершені.

Початкове вікно дозволяє створити локальний реліз, відкрити збережений файл, імпортувати
Chrome handoff або відкрити приклад із вигаданими даними. Для локального оцінювання Jira
та Google не потрібні.

## Дошка естимації

- П'ять колонок: оцінка ТЛ, уточнення, погодження скоупу, підготовка QA, готово. Картки
  містять ключ, назву, відповідального та оцінки; є пошук, кількість і підсумки.
- Додавання кількох ключів, Jira-посилань, CSV/TXT/TSV; XLSX із вибором аркуша та колонки.
  Перевіряється проєкт і дублікати.
- Локальні dev-частини з назвою й оцінкою, матеріали ТЛ/QA, запитання й відповіді, AC/DoD.
  Для планування не потрібні вигадані Jira-підзадачі чи запис оцінки на сервер.
- Зміни матеріалів одразу потрапляють у документ: CmdS зберігає їх без додаткової кнопки.
  Зміна задачі й повторне відкриття не втрачають введений текст.
- Передача ТЛ → QA, повернення та повторна оцінка скидають відповідні погодження. QA = 20%
  dev або явна оцінка; підсумок = dev + QA, буфер окремо.
- Експорт справжнього XLSX лише для готового скоупу, без буфера і внутрішньої
  декомпозиції.
- Chrome handoff version 1 та збережений стан дошки імпортуються зі збереженням
  оригінального JSON. Несумісний проєкт відхиляється.
- Типова команда зберігається окремо для команди й Jira-сервера. Локальний вибір ролі
  служить для планування; мережевий запис вимагає перевіреної Jira-особи.

## Перенесені модулі

**Gantt:** читання всіх сторінок Jira-борду, JQL, налаштування полів дат,
ієрархія/згортання, пошук, приховування готових, сортування, масштаб, прогрес, стрілки
залежностей. Підтверджені дати, локальні зміни, прогноз і підсумки дочірніх задач
розрізняються. Без обох дат задача залишається без розкладу. Локальний редактор,
перенесення смуги й зміна завершення; приватні FS/SS/FF/SF із перевіркою циклів і
конфліктів. Неробочі дні та типова тривалість прогнозу зберігаються у файлі. Плани й
налаштування розділені за бордом і Jira-сервером.

**Status:** кругова діаграма всіх статусів із кількістю й часткою, вибір статусу фільтрує
список.

**Reporting:** ручний генератор, локальна історія, stand-up EN/UK, PDF, board health,
plan/fact і явна недоступність даних. Формули звіряються з fixtures існуючої
TypeScript-реалізації.

**Налаштування Chrome:** імпорт setup JSON переносить origin, проєкт/борд, JQL, поля дат,
календар і типові тривалості; Reporting бере completedStatusIds. Оригінальний JSON
зберігається. Спеціальні hierarchy/story-points/sprint поля поки не застосовуються, про це
показується явне повідомлення.

**Файли:** локальний `.pvrelease`, імпорт/експорт workspace JSON, Excel оцінок. Збережений
snapshot дозволяє відкривати Gantt/Status без мережі.

## Jira і Google Drive

Jira Cloud REST v3, email/API token, Keychain. Якщо Keychain недоступний, перевірене
підключення може працювати в поточному сеансі з явним повідомленням. Токени не записуються
в реліз.

Записи коментарів, підзадач, оцінок, AC/DoD, Fix Version, дат, статусу та виконавця
підготовлені як окремі пропозиції з переглядом. Перед виконанням перевіряються особа,
origin, доступні поля/переходи та актуальність задачі; намір фіксується в локальному
журналі. Автоматичного повторення записів немає. Під час тестування реальні Jira-дані не
змінювались.

Google Drive має реалізацію збереження окремої копії файлу через OAuth/Drive API. У збірці
немає зареєстрованого Google OAuth client ID, тому реальний вхід і завантаження не
підтверджені. Desktop Drive та Apps Script не є вимогами для збереження копії. Прототип
Apps Script призупинений. Спільне одночасне редагування ще не реалізоване.

## Докази й межі перевірки

Незалежні звіти:

- [Аудит відповідності замовленню](native-macos-independent-scope-audit.md).
- [Початкове exploratory-тестування](native-macos-independent-exploratory-audit.md).
- [Незалежна регресія переробки](native-macos-independent-rework-regression.md).

Незалежна регресія підтвердила локальний шлях: створення → матеріали/оцінки → CmdS →
повторне відкриття → ТЛ → QA → готово → реальний XLSX із сумою 7 днів. Також перевірені
Status, локальні дати Gantt і Chrome handoff. Цей висновок стосується конкретної збірки,
зазначеної у звіті.

Після неї додано календар прогнозу, редагування Jira-дат/статусу/виконавця через перегляд,
типізовані локальні залежності, налаштування Gantt та ізоляцію планів за бордами. Вони
мають автоматичні перевірки; результати додаткової UI-регресії фіксуються окремо.

Повну відповідність перенесення ще не підтверджено: потрібні наскрізні перевірки на
реальній Jira, завершення підтримки нестандартних hierarchy/story-points/sprint mappings
Chrome setup, крайових випадків ієрархії та фінальна звірка всіх критеріїв P1–P8/E1–E8.
Jira Data Center не підтримується. Google-вхід і спільна робота двох користувачів не
перевірені. Успішні локальні тести не є підтвердженням цих сценаріїв.

## Додаткова перевірка у вікні після розблокування Mac

19 жовтня 2026 року, основний агент, остання перепакована збірка:

- Відкрито власну копію synthetic workspace; Gantt відновив REG-2 23–28 жовтня, вихідні
  Jira-дати лишились у snapshot.
- Зміна календаря на [Нд, Вт, Сб] і тривалості сторі на 6 днів через UI, CmdS: ті самі
  значення перевірено в записаному JSON.
- Через кнопку імпорту Chrome setup перенесено борд, JQL, поля дат, календар [Нд, Сб],
  task=4/story=8; UI явно повідомив, що storyPointsFieldId збережено, але не застосовано.
- Ця перевірка виявила застарілий локальний UI-стан після імпорту. Виправлено
  синхронізацію налаштувань і перебудову Gantt при зміні origin/борду.
- Повторення на виправленій збірці: у відкритому Gantt задано story=9 і додано Вт;
  повторний імпорт того самого setup негайно повернув story=8/task=4 і прибрав Вт. CmdS
  записав ці значення. Перезапуск перед цим також відновив імпортований календар.
- Основний набір: 65 тестів пройшли. Після уточнення перевірки setup і календаря дві
  відповідні автоматичні перевірки повторно пройшли; остання збірка успішно скомпільована
  й підписана.
- Незалежний агент окремо підтвердив 4 типи links, дублікат/conflict, відновлення масштабу
  після reopen і snapshot-import; див. доповнення regression-звіту. Новий календар
  перевіряв основний агент, його не названо незалежно прийнятим.

Це синтетичні локальні файли. Мережевих записів у Jira/Drive не було.
