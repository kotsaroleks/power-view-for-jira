# Drive lease: призупинений прототип

Рішення з додатковим Apps Script-сервісом призупинено після обговорення з користувачем.
Наведене нижче збережене як технічний експеримент, а не вимога налаштування.

Це не готова інтеграція й не доказ A4–A6. Локально перевірені протокол і помилки;
конкурентність реального Google-сервера, ідентичність користувачів та квоти ще не
перевірені. Функцію не підключено до редагування у UI, тому застосунок чесно працює з
локальними файлами.

## Механізм

Один Apps Script API executable виконує всі зміни тестового файла. `getScriptLock()`
охоплює читання, перевірку lease і повний запис Drive. У файлі зберігаються документ,
ревізія, покоління lease, hash секрету та квитанції останніх 100 запитів. Власний секрет
генерує клієнт і не записує його відкритим текстом у спільний файл. Одна операція
`setContent` записує і документ, і метадані commit.

`read` не продовжує lease. `activity` призначена лише для дій людини. Через 30 хвилин
старий власник не проходить серверну перевірку; `read` показує файл вільним без cron.
Повтор того самого `requestID` з тим самим вмістом повертає історичну квитанцію, не
виконує запис вдруге й не доводить, що lease досі активний.

Swift-клієнт у `DriveLease.swift` використовує монотонний годинник від початку запиту,
відкликає локальні права після невідомого результату й забороняє паралельні мутації своєї
сесії. Google-транспорт приймає OAuth token provider; повного OAuth UI ще немає. Після
невизначеної відповіді потрібна звірка квитанції; автоматичного повтору збереження немає.

## Підготовка ізольованого середовища

1. Створити стандартний тестовий Google Cloud-проєкт, увімкнути Apps Script API та Drive
   API.
2. Створити Apps Script-проєкт із `LeaseService.js` і прив'язати до того самого
   Cloud-проєкту.
3. У тестовій папці Drive створити звичайний JSON-файл з наведеним нижче envelope.
4. У Script Properties встановити `RELEASE_FILE_ID` та `MEMBERS` (JSON-масив двох тестових
   email). Це несекретні налаштування; Jira-токенів, Google refresh token чи client secret
   тут бути не має.
5. Розгорнути як **API executable** лише для тестових користувачів. Зберегти deployment
   ID.
6. Налаштувати OAuth consent і Desktop client у спільному Cloud-проєкті. Кожен із двох
   користувачів проходить власне погодження. Повний OAuth UI/refresh/keychain для Google
   належить до наступного інтеграційного кроку; токени не передавати в чат чи Git.
7. Перевірити `Session.getActiveUser().getEmail()` для обох користувачів. Порожня особа
   має завершуватися відмовою, а не підставленням email із запиту.

```json
{
  "schemaVersion": 1,
  "generation": 0,
  "revision": 0,
  "document": {},
  "lease": null,
  "receipts": []
}
```

Виклик: `POST https://script.googleapis.com/v1/scripts/{deploymentId}:run`, функція
`releaseOperation`, один параметр — об'єкт запиту. Для локального тесту:

```sh
node --test prototypes/drive-lease/LeaseService.test.mjs
```

## Обов'язкова жива перевірка

| Сценарій                                               | Успішний результат                                                         |
| ------------------------------------------------------ | -------------------------------------------------------------------------- |
| Два одночасні `acquire` з різних Mac                   | Один успіх, другий Busy                                                    |
| Два Mac однієї людини                                  | Також лише один активний client secret                                     |
| Polling понад 30 хвилин без редагування                | Не продовжує lease; інший клієнт може захопити файл                        |
| Старий редактор після нового acquire                   | Його save та activity відхиляються                                         |
| Мережа зникла до/після `setContent`                    | Немає неправдивого успіху або повторного commit; квитанція дозволяє звірку |
| Збій застосунку під час редагування                    | AES-GCM-чернетка відновлюється автором без мережі                          |
| Інший учасник змінив спільну версію                    | Автор бачить diff і переносить лише вибрані поля                           |
| Відсутні права Drive, OAuth expired, Apps Script quota | Видима помилка; редагування не дозволяється                                |

Локальний VM-harness підставляє LockService і DriveApp. Він не моделює реальні мережеві
гонки Google і не може замінити таблицю живих перевірок.

## Межі кандидата

- Конфігурація зараз містить один файл на deployment; реєстр кількох релізів ще не
  реалізовано.
- Немає захисту від прямого ручного запису в Drive поза цим протоколом.
- Зберігання та аудит lease в самому файлі потребують перевірки дозволів, квот і розміру
  на реальних даних.
- Окремий доступ до Google Drive в UI, вибір папки, створення файла й OAuth refresh ще не
  підключено.
- Цей службовий посередник не є хмарним розкладом етапу 2.
